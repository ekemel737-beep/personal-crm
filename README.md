# Личная CRM

Приложение для своих контактов: кто человек, откуда знакомы, телефон, почта и заметки о разговорах.

Идея и главный сценарий — в [specs/01-продуктовая-идея.md](specs/01-продуктовая-идея.md).

## Что нужно установить

- [Node.js](https://nodejs.org/) 20 или новее
- [pnpm](https://pnpm.io/)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) — в нём работает база данных

> Если PowerShell пишет «выполнение сценариев отключено», выполните один раз
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` и откройте терминал заново.

## Первый запуск

1. Скопируйте `.env.example` в `.env` и заполните значения: имя пользователя базы, пароль, имя базы и строку подключения `DATABASE_URL` из них же.
2. Запустите Docker Desktop, затем в папке проекта:

   ```
   pnpm install
   docker compose up -d
   pnpm db:migrate
   pnpm db:seed
   ```

   `pnpm db:seed` добавит 1000 тестовых контактов с заметками. Он сработает только на пустой базе — если контакты уже есть, ничего не изменит.

3. Запустите приложение:

   ```
   pnpm build
   pnpm start
   ```

   и откройте http://localhost:3000

Для разработки вместо `build` + `start` можно запускать `pnpm dev` — изменения в коде будут видны сразу.

## Повседневное

| Что сделать                       | Команда                  |
| --------------------------------- | ------------------------ |
| Запустить базу                    | `docker compose up -d`   |
| Остановить базу (данные остаются) | `docker compose stop`    |
| Запустить приложение              | `pnpm start` (после `pnpm build`) |
| Посмотреть данные в базе          | `pnpm db:studio`         |
| Проверить главный сценарий        | `pnpm test:e2e`          |

`pnpm test:e2e` открывает браузер Edge, сам добавляет контакт, ищет его, дописывает заметку и проверяет, что всё сохранилось. Созданный тестом контакт он потом удаляет. Перед запуском тестов приложение должно быть собрано (`pnpm build`).

## Изменение структуры базы

Таблицы описаны в `src/db/schema.ts`. После изменения:

```
pnpm db:generate
pnpm db:migrate
```

Файл миграции из папки `drizzle/` закоммитьте вместе с кодом: на сервере миграции применятся сами при выкатке.

## Выкатка на сервер

Приложение работает на https://app.ekemel.ru (сервер 195.58.55.115).

### Как выкатить новую версию

Закоммитьте изменения и отправьте их в ветку `main`:

```
git push
```

Дальше всё происходит само, примерно за 5 минут:

1. GitHub Actions собирает Docker-образ приложения и кладёт его в GitHub Container Registry. Тег образа — SHA коммита.
2. GitHub заходит на сервер ключом деплоя и запускает `deploy/deploy.sh`:
   - миграции базы применяет отдельный разовый контейнер; если миграции упали, новая версия не запускается и продолжает работать старая;
   - запускается новая версия приложения;
   - проверка `/health` на самом сервере и через https://app.ekemel.ru/health;
   - старые образы удаляются, остаются текущий и предыдущий.

Как идёт выкатка — на вкладке **Actions** в репозитории на GitHub. Зелёная галочка — новая версия работает. Красный крестик — выкатка упала; сама она ничего не откатывает.

### Как откатиться

Только вручную. Вернуть предыдущую версию (её образ хранится на сервере):

```
ssh crm 'sudo -u deploy bash /srv/personal-crm/deploy/deploy.sh $(sudo cat /srv/personal-crm/state/previous-tag)'
```

Вернуть любую более старую версию: на GitHub во вкладке **Actions** откройте выкатку нужного коммита и нажмите **Re-run all jobs**.

Миграции базы при откате назад не отменяются.

### Что где лежит на сервере

| Что | Где |
| --- | --- |
| Пароль базы | `/srv/personal-crm/.env` — права 600, владелец `deploy`; шаблон — `deploy/.env.example` |
| Скрипты выкатки | `/srv/personal-crm/deploy` — копируются из `deploy/` при каждой выкатке |
| Какая версия сейчас и до неё | `/srv/personal-crm/state/current-tag` и `previous-tag` |
| База данных | Docker volume `prod_db-data` |
| Логи приложения | `ssh crm sudo docker logs --tail 100 prod-app-1` |

Приложение слушает только `127.0.0.1:3100` на сервере, снаружи до него доходят через nginx (`/etc/nginx/conf.d/app.ekemel.ru.conf`). Ключ деплоя хранится в секрете репозитория `DEPLOY_SSH_KEY`.
